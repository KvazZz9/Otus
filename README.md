Задание :
развернуть 4 виртуальных машины терраформом в Яндекс.Облаке или на локальном стенде;
1 виртуалка - Nginx-балансировщик с публичным IP адресом. Показать конфигурацию для балансировки методами round-robin и hash (выбор переменных самостоятельный);
2 виртуалки - Nginx-фронтенд со статикой и бэкенд на выбор студента. В качестве бэкенда может использовать любой отладочный контейнер (образ vscoder/webdebugger) или заглушку;
задание со звездочкой* в качестве бэкенда использовать полноценную CMS (Wordpress, Joomla, Drupal, MediaWiki или любое на стеке Uwsgi/Unicorn/PHP-FPM/Java) и запустить виртуалку с одним экземпляром БД для работы с бэкендами.

Реализация :

Задача реализованна в локальной инраструктуре с момощью локального gitlab и кластера esxi под управлением vcenter. Доступ к vcenter осужествляется с помощью логина и пароля который хранится в локальном vault доступ к vault по токену(добавлен в переменные проекта), в качестве инструмента оркестрации используется tofu, state tofu так же хранит в локальном гите обращаясь к нему по средствам токе который генерирует гит, в качестве веб сервера выбран angie.

CI/CD файл состоит из 4 стадий:
plan - проверяем правильность конфига тофу, сохраняем вывод tofu plan  в переменную
build - поднимаем по ранее сохраненному плану ytj
destroy - добавленно для удобства последующего удаления поднятой структуры
angie - конфигурируем машины


в конфигурации используем следующие ип, выделить публичный ip , в рабочей инфре балансеру проблематично поэтому ограничился внутренним, на всех вм используется локальный днс в который предварительно занес 4 соответствующие записи для удобства :
balance01 192.168.117.200 балансировщик (сюда стучимся)
front01  192.168.117.210 фронт1 (сюда попадаем с абалнсировщика и улетаем на back01)
front02  192.168.117.211 фронт2 (сюда попадаем с абалнсировщика и улетаем на back01)
back01   192.168.117.220 back1 (тут поднимаем докер конт с webdebugger и посредствам angie пробрасываем с 80 входящего на 127.0.0.1:8080 локальный в контейнер)
